# 真机复测清单

本清单用于补齐一个长期缺口：**此前所有改动都只经过本机四通道（`swift build` / `swift test` /
iOS 模拟器编译 / `xcodebuild`），没有任何一项在真机上验证过行为。** 下面每一条都对应一处
「代码改了、逻辑推演过、但没人实测过」的功能。

## 怎么用

- 按分区从上往下走，灵动岛放最前（唯一已知未解决的 bug）。
- 每条都是 `步骤 → 期望`。**期望不符就是 bug**，请把那一条编号和实际现象发我。
- 需要留证据的地方标了「抓日志」，方法见文末。
- 标 【高风险】的表示「我知道这里风险最高」；标 【未验证】的表示「只是没测过，逻辑上应该没问题」。

## 0. 环境准备

- 一台真机 iPhone（灵动岛机型，否则灵动岛相关只能测锁屏实时活动）。
- 系统时间保持自动。
- 建议先用 Release/TestFlight 包测，Debug 包在通知与后台时限上和 Release 有差异。
- 记录当前 App 版本号与提交 SHA（设置页底部或 `git rev-parse --short HEAD`）。

## 1. 灵动岛 / 实时活动 【高风险】

### 1.1 时间胶囊能否上岛（**已知可能完全不出现，最高优先**）

- ☐ 设置 → 提醒与时间胶囊 → 确认总开关是**开**。
- ☐ 系统 设置 → 清和日历 → 确认「实时活动」是**开**。
- ☐ 建一条今天稍后的日程（如 30 分钟后），回到桌面。
- ☐ **期望**：灵动岛上出现时间胶囊卡片，含标题与剩余时间；锁屏也能看到同一张卡。
- ☐ 如果没出现：抓日志，搜 `时间胶囊未上岛`，把这行连同前后各 5 行发我。四种原因文案
  分别指向不同分支，见代码 `Sources/LunisolarCalendarApp/Services/TimeCapsuleCoordinator.swift`。

> 背景：这条是**回归**——用户反馈「以前能用，最近才不行」。四道守卫已各自加了留痕日志，
> 只差这一行日志就能定位。另需留意是否出现 `时间胶囊上岛失败：` （系统拒绝了启动请求）。

### 1.2 倒数日上岛（手动路径，绕开时间胶囊）

- ☐ 日历 → 工具菜单 → 倒数日 → 新建一条 → 点行内「上岛」按钮。
- ☐ **期望**：按钮变成「在岛上」；灵动岛/锁屏出现倒计时卡片。
- ☐ 再点一次「下岛」→ **期望**：卡片消失，按钮变回「上岛」。
- ☐ 关掉系统「实时活动」总开关 → 点「上岛」→ **期望**：弹「灵动岛未开启」并给出去设置按钮，
  不是静默失败。
- ☐ 关掉 App 内「提醒与时间胶囊」→ 点「上岛」→ **期望**：弹出的文案指向 App 内开关，
  不是指向系统设置。

### 1.3 时间胶囊与倒数日互斥 【未验证】

- ☐ 让倒数日先上岛，再让时间胶囊该上的日程到点。
- ☐ **期望**：时间胶囊让位、不抢占；倒数日下岛后时间胶囊能自动接管。
- ☐ 反向再来一遍。
- ☐ 反复切几次，确认不会出现「两边都以为对方占着岛」而谁都不上岛的死锁（【高风险】，这是我最担心的
  一类 bug：仲裁器按系统活动列表推导占用者，`.ending` 残留会让时间胶囊永远让位）。

### 1.4 实时活动点击回 App 【未验证】

- ☐ 点灵动岛上的倒数日卡片 → **期望**：打开 App 并切到「倒数日」，该条有淡蓝高亮。
- ☐ 关闭倒数日页，再点一次卡片 → **期望**：仍能打开并高亮（不应只为第一次生效）。
- ☐ 点时间胶囊卡片 → **期望**：打开 App 并停在对应日期的日程详情。
- ☐ 【重点】这条改动是最近才做的：`AppLifecycleCoordinator` 前台立即消费深链。此前 App 已在前台时
  点卡片会被静默丢弃到下次前后台切换才生效——请在「App 已在前台」这个状态下也点一次。

### 1.5 实时活动内容时效 【未验证】

- ☐ 倒数日卡片长按放大 → **期望**：完整信息（标题、日期、剩余天数/倒计时）无截断。
- ☐ 全天事件的实时活动跨过当天 24:00 → **期望**：不再霸占灵动岛（应已过期下岛）。
- ☐ 点通知里的「稍后提醒」→ **期望**：实时活动保留/恢复，不是被一起清掉。

## 4. 深链 【高风险】

用 Safari 地址栏逐条输入，或做快捷指令：

| 链接 | 期望 |
|---|---|
| `qinghe://calendar` | 打开 App，停在日历页 |
| `qinghe://calendar/date/2027-02-06` | 日历跳到该日期并选中 |
| `qinghe://ai` | 打开 AI 助手 Tab |
| `qinghe://event/<某事件UUID>` | 打开该事件的编辑页（UUID 从别处拿） |
| `qinghe://countdown/<某倒数日UUID>` | 打开倒数日并高亮该条 |
| `qinghe://` （空 host） | 不崩溃、不改导航状态 |
| `qinghe://event/不是UUID` | 不崩溃、不改导航状态 |

- ☐ 【重点】每一条都请在 **App 已在前台** 与 **App 已完全退出** 两种状态下各测一次。
  冷启动路径依赖 `handlePendingDeepLink()` 的 pending 存储，是和前台路径不同的代码分支。
- ☐ iPad 上 `qinghe://countdown/<UUID>` 额外确认两件事：切到倒数日节、该条有高亮；
  然后切到「日历」节确认**不会**自动弹出倒数日页（【重点】这条是我最近才修的）。

## 8. AI 助手 【高风险】

用户反馈过「输入交互不起作用」，请重点走一遍：

- ☐ 输入文字 → 点「解析并预览」→ **期望**：出预览卡片，标题与时间解析正确。
- ☐ 点「取消」→ **期望**：只收起预览，**输入内容保留**（不应清空）。
- ☐ 点「确认创建」→ **期望**：事件入库，出成功提示（行内提示，不是模态弹窗），
  输入框清空并把焦点还给输入框，便于连续录入。
- ☐ 一键清空按钮（输入框右侧 xmark）→ **期望**：清空后占位串不被当作输入内容，
  下一次输入不会拼在占位串后面。
- ☐ 输入一个**已过去的时间**（如「今天下午 2:00」，且现在已过 2 点）→ **期望**：弹出
  「无法解析」并提示加「明天/后天」或具体日期，不是静默失败。
- ☐ 语音输入：用系统键盘的听写输入 → **期望**：识别文本正常进入输入框并可解析
  （App 自身不带麦克风按钮）。
- ☐ 查询意图：「今天有什么安排」→ **期望**：返回当天日程列表。
- ☐ 修改意图：「把明天 3 点的会改到 5 点」→ **期望**：定位到正确事件并给出新时间预览。
- ☐ 删除意图：「删掉明天的会」→ **期望**：先预览再确认，不直接删。
- ☐ 【重点】重复日程：「把每周三的会改到 5 点」→ **期望**：预览里显示的是**命中那一次**的
  时间，并有橙色警告说明会影响到整条重复规则。
- ☐ 预览卡通过「关闭」退出后，再次解析应正常（不应卡住）。
- ☐ 键盘弹出/收起时预览卡与输入框不发生遮挡、跳动。

## 附录 B：怎么抓日志

主 App 日志走 `os.Logger`，子系统和分类固定：

- subsystem：`com.lumingfeng.lunisolarcalendar`（Bundle ID）
- category：`App`（普通）、`Sync`（同步）

抓取方式（任选）：

1. **Console.app**（Mac + 数据线）：选左侧真机 → 右上搜索框输入
   `subsystem:com.lumingfeng.lunisolarcalendar`，或直接搜中文关键词
   `时间胶囊未上岛` / `时间胶囊上岛失败`。先点「开始」再在手机上复现。
2. **手机端**：若已配置 Sysdiagnose，触发后从分析数据里取日志。
3. 抓不到 App 日志时，退而求其次记录：现象发生时间、当时 App 是前台/后台/未启动、
   系统「实时活动」与 App 内「提醒与时间胶囊」两个开关的状态。
