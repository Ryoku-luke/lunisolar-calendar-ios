# 清和日历 · App Store 上架指南

本文档提供从 Archive 到上架 App Store 的完整流程。

---

## 一、上架前准备

### 1. 版本号

| 字段 | 位置 | 说明 |
|---|---|---|
| `CFBundleShortVersionString` | Info.plist | 版本号（如 1.0.0），每次上架递增 |
| `CFBundleVersion` | Info.plist | Build 号（如 1），每次提交递增 |

### 2. App Icon

- 主图标 1024×1024 PNG，**无透明通道**（App Store 强制要求）
- 运行 `bash Tools/gen-app-icons.sh` 生成全部尺寸
- 春节限定备用图标同样需要全尺寸 PNG

### 3. 截图

| 设备 | 尺寸要求 |
|---|---|
| iPhone 6.7" | 1290×2796（iPhone 16 Pro Max） |
| iPhone 5.5" | 1242×2208（iPhone 8 Plus） |
| iPad Pro 12.9" | 2048×2732 |

至少需要 1 张 6.7" 截图（其他可选）。

---

## 二、Archive 与上传

### 1. Archive

1. Xcode → 选择 **Any iOS Device (arm64)** 作为目标
2. Product → Archive
3. 等待构建完成，Organizer 窗口自动弹出

### 2. 验证

1. Organizer → 选中 Archive → Validate App
2. 勾选 **Upload your app's symbols**（崩溃符号化）
3. 确认无错误后上传

### 3. 上传到 App Store Connect

1. Organizer → Distribute App → App Store Connect → Upload
2. 等待上传完成（通常 5-15 分钟）

## 三、App Store Connect 配置

### 1. App 信息

| 字段 | 内容 |
|---|---|
| 名称 | 清和日历 |
| 副标题 | 公历农历 · 黄历宜忌 · 节日主题 |
| 类别 | 生活 > 日历，或 效率 |
| 年龄分级 | 4+（无暴力/成人内容） |

### 2. 隐私标签（Privacy Labels）

本 App **不收集、不共享、不用于追踪**任何用户数据：

| 数据类型 | 是否收集 | 用途 | 是否追踪 | 是否关联身份 |
|---|---|---|---|---|
| 日历事件 | 否 | — | 否 | — |
| 联系人信息 | 否 | — | 否 | — |
| 位置 | 否 | — | 否 | — |
| 标识符 | 否 | — | 否 | — |

> CloudKit 同步的日历数据属于用户主动管理的个人数据，存储在用户个人 iCloud 中，开发者无法访问。

### 3. 关键词建议

`日历, 农历, 黄历, 宜忌, 节日, 提醒, 生日, 倒计时, 中国日历, 万年历`

### 4. 描述

```
清和日历 —— 公历农历对照、黄历宜忌、节日主题、智能提醒的中国日历。

【核心功能】
• 公历农历双向查询，1900-2100 年全覆盖

【设计】
• iOS 26 Liquid Glass 液态玻璃
• 节日自适应主题色
• 按压反馈动画
• iPad 双栏自适应布局
```

## 四、审核要点

### 1. 高通过率要点

- ✅ 所有隐私权限文案清晰说明用途
- ✅ 不强制要求 iCloud 登录才可使用核心功能
- ✅ Widget 在没有数据时显示合理占位（不崩溃）
- ✅ 离线模式下基本功能（日历查看、本地提醒）可用
- ✅ 不展示任何外部链接到支付页面（除非是 IAP）

### 2. 可能被拒的点

| 问题 | 规避 |
|---|---|
| 权限弹窗时机过早 | 仅在用户主动触发导入时请求权限 |
| CloudKit 不可用时崩溃 | 已做 `CKContainer.default()` 延迟装配 + Mock fallback |
| Widget 崩溃 | 快照过期显示占位，不强制解包 |
| 农历数据越界 | 1900-2100 外显示提示，不显示假数据 |

## 五、版本发布流程

```
开发完成 → 单元测试 80/80 通过 → Archive → Validate → Upload
  → App Store Connect 填写元数据 → 提交审核 → 审核通过 → 发布
```

### 热修流程

```
修复 Bug → 递增 CFBundleVersion → Archive → Upload → 提交审核
```
