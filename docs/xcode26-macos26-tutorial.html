1整体流程一览

本项目是 SwiftPM 纯工程（仓库里没有 .xcodeproj）。Xcode 打开 Package.swift 会自动识别，但要跑 iOS App / Widget / 真机，仍需手动建一个宿主 iOS App Target。

2环境要求与自检

推荐使用最新 macOS 26（Tahoe）+ Xcode 26 组合，Swift 6 严格并发模式。

3项目结构与 Target 体系

双 Library 拆分：LunarCore 纯算法（可被 CLI 复用），LunisolarCalendarApp 含 UI + 业务。

图 2 · Package.swift 的 4 个 Target 与依赖关系
⚠️ 关键设计 LunarCore 只包含 LunarDate.swift 和 Huangli.swift 两个纯算法文件。 LunisolarCalendarApp 通过 exclude 把这两个文件排除（避免重复编译），再以依赖方式引入。 这样 gen_huangli_db CLI 只链接 LunarCore，不会触发 @main 符号冲突。

4用 Xcode 26 打开 Package.swift

1

启动 Xcode 26，菜单 File → Open…（⌘O），选择仓库根目录的 Package.swift。

2

Xcode 会自动解析 SPM 工程，左侧 Project Navigator 顶部出现 LunisolarCalendar 包，展开可见 Sources、Tests、Tools。首次打开会触发 Resolve Package Dependencies（本项目无外部依赖，秒级完成）。

💡 为什么没有 .xcodeproj？ 本项目刻意保持 SwiftPM 纯工程结构。Xcode 打开 Package.swift 时会在 DerivedData 自动生成工程，无需手动保存。这样仓库干净、跨平台（Linux CI 用 swift build）。

5创建宿主 App Target

SPM 工程不会生成可执行的 iOS App。需要手动建一个空 SwiftUI App 作为宿主，把 LunisolarCalendarApp library 嵌入进去。

1

菜单 File → New → Target… → 选 iOS → App，点 Next。

2

填写选项：

  • Product Name：LunisolarCalendar（或任意名字，只要与 SPM product 名不同即可）
  • Interface：SwiftUI
  • Language：Swift
  • ❌ 不勾 Use Core Data / Include Tests / Use Swift Data
3

新 target 创建后，进入 Project → Target → General → Frameworks, Libraries, and Embedded Content，点 +，在 Package Products 分组下选 LunisolarCalendarApp，状态设为 Embed & Sign。

4

删除模板生成的 ContentView.swift 和 LunisolarCalendarApp.swift（Xcode 默认建的那个空壳）。

5

在宿主 target 的文件夹里新建入口文件 HostApp.swift（不要放进 Sources/LunisolarCalendarApp）：

import SwiftUI
import LunisolarCalendarApp

@main
struct HostApp: App {
    var body: some Scene {
        WindowGroup {
            AdaptiveRootView()
                .environment(EventStore.shared)
        }
    }
}
6

在 Signing & Capabilities 设置你的 Team，并把 Bundle Identifier 改成唯一值（如 com.yourname.lunisolar-calendar）。

❌ 常见错误 同时把 LunarCore 和 LunisolarCalendarApp 都加进宿主 target 的 Frameworks，会报 duplicate symbols。因为 LunisolarCalendarApp 已依赖 LunarCore，只需加 LunisolarCalendarApp 即可。

6编译 & 在模拟器运行

Xcode 界面

  • 左上角 Scheme 选宿主 App target（不是 SPM 生成的 LunisolarCalendarApp library）。
  • 设备选 iPhone 16 (iOS 26) 或 iPad Simulator。
  • ⌘R 运行；⌘B 只编译；⌘. 停止。

命令行（CI / 脚本）

# 模拟器 Debug 构建
xcodebuild -scheme LunisolarCalendar \
    -destination 'platform=iOS Simulator,name=iPhone 16' \
    -configuration Debug build

# 真机 Release 构建（需要签名）
xcodebuild -scheme LunisolarCalendar \
    -destination 'generic/platform=iOS' \
    -configuration Release build CODE_SIGNING_ALLOWED=YES

常见编译错误速查

8Widget 小组件 Extension

已实现 3 种 Widget，统一在 LunisolarWidgetBundle() 注册。

样式入口说明
今日黄历概览HuangliTodayWidget宜忌 + 冲煞 + 农历日期
农历日期卡片LunarDateWidget农历月日 + 节日 + 生肖
今日待办进度EventProgressWidget完成比例 + 近期待办条数

Xcode 接入步骤

1

File → New → Target… → Widget Extension，Product Name 填 LunisolarWidget，不勾 "Include Configuration App Intent"。

2

进入 LunisolarWidget target → General → Frameworks → + → Package Products → LunisolarCalendarApp → Embed & Sign。

3

删掉模板生成的 Widget 文件，替换为：

import WidgetKit
import SwiftUI
import LunisolarCalendarApp

@main
struct LunisolarWidgetBundle: WidgetBundle {
    var body: some Widget {
        HuangliTodayWidget()
        LunarDateWidget()
        EventProgressWidget()
    }
}
4

App Group 配置（让宿主 App 与 Widget 共享快照数据）：

  • 宿主 App + Widget 两个 target 都在 Signing & Capabilities 加 App Groups，勾选 group.com.yourname.lunisolar。
  • 宿主 App 入口里设置：EventStore.shared.widgetAppGroupID = "group.com.yourname.lunisolar"
💡 Widget 调试 Run Scheme 选宿主 App（Widget 不能单独 Run）。真机长按桌面 → + → 搜 "Lunisolar" 添加。 数据由 EventStore 写 snapshot JSON，Widget 下次刷新（系统 15 分钟节流）时读取。

9权限：通知 / 通讯录 / 日历

Info.plist 已预置 usage description，真机首次使用弹窗询问。

Key场景
NSContactsUsageDescription导入联系人生日 → 农历/公历纪念日
NSCalendarsUsageDescription / NSCalendarsFullAccessUsageDescription导入/导出 ICS（EventKit）
UNUserNotificationCenter设置提醒时排程本地通知

通知申请（已内置）

NotificationManager.shared.requestAuthorization()  // Settings 页首次使用触发

用户允许后才能排程 UNCalendarNotificationTrigger。若权限被拒，markNotified 不会置 true，授权后 rescheduleAllReminders 会重排。

通讯录导入（已内置）

ContactsImportProvider().fetchBirthdays()  // 返回 [SystemContactBirthdayDTO]

内部自动申请 CNContactStore 授权，拒绝后返回空数组，不崩溃。

10iCloud · CloudKit 同步

前提配置

  1. 宿主 App + Widget target 都在 Signing & Capabilities 加 iCloud，勾选 CloudKit，选/建 Container（如 iCloud.com.yourname.lunisolar）。
  2. 同步代码用 #if canImport(CloudKit) 隔离，Linux CI 走 Mock，真机自动切 Real。

Mock vs Real 切换

  • 默认 MockCloudKitProvider（纯内存，离线测试 / swift test）。
  • 真机 iCloud 由 EventSyncCoordinator 在用户开启同步时装配 RealCloudKitProvider。
⚠️ 不要无条件调用 CKContainer.default() iOS Simulator 没 CloudKit entitlement 时会 EXC_BREAKPOINT 崩溃。 本项目把 RealCloudKitProvider 创建延迟到 SettingsView 的 Toggle 打开时，用 do/catch 探测 isAvailable，失败弹 toast。

调试技巧

  • CloudKit Dashboard：icloud.developer.apple.com/dashboard
  • Console.app 过滤 Lunisolar 看 AppLogger.sync 日志。
  • 清本地 iCloud 缓存：Settings → Apple ID → iCloud → Manage Storage → 你的 App → Delete All。

11黄历离散数据库生成器

位置 Tools/gen_huangli_db/main.swift，只依赖 LunarCore，独立 CLI。

生成离散库

swift run gen_huangli_db Sources/LunisolarCalendarApp/Resources/huangli_db.json

输出格式

{
  "v": 1,
  "range": ["2024-01-01", "2028-12-31"],
  "count": 1826,
  "days": {
    "2026-09-01": {
      "y": ["祭祀", "祈福"],
      "j": ["出行", "开市"],
      "c": "鼠", "s": "南", "w": "海中金",
      "g": "喜神:东北 财神:西南"
    }
  }
}
💡 扩展年份 改 main.swift 里 start / end 的 DateComponents 即可。农历数据表覆盖 1900-2100，任意连续区间都能生成。 生成器强制走纯算法（不查已有库），避免循环写。运行后 HuangliDBProvider 优先查库，缺失才 fallback 到算法。

12iPad 适配

CalendarMonthView 手势代码用 #if canImport(UIKit) 隔离，避免 macOS/Linux 编译缺失 GestureState。

  • 双栏布局：AdaptiveRootView 根据 horizontalSizeClass 自动切 NavigationSplitView（左月历 + 右详情）。
  • 横竖屏：Info.plist 已声明 UIInterfaceOrientationLandscapeLeft/Right。
  • Widget：iPad 默认 systemMedium / systemLarge 自动适配。

真机调优：Product → Destination → iPad Pro 13" (M4)，横屏默认双栏、竖屏折叠单栏，符合 HIG。

13Archive & App Store 发布

13.1 准备工作

  1. 付费 Apple Developer 账号（$99/年）。
  2. developer.apple.com/account 注册 App ID：Bundle ID 与 Xcode Signing 一致；Capabilities 勾 iCloud + CloudKit + Push Notifications。
  3. 如需 Widget，建 App Group 并关联到 App ID。

13.2 版本号

  • CFBundleShortVersionString：语义化版本（如 1.2.0），App Store 展示用。
  • CFBundleVersion：build 号，每次上传必须 +1（整数）。

13.3 Archive

xcodebuild \
  -scheme LunisolarCalendar \
  -archivePath LunisolarCalendar.xcarchive \
  -destination 'generic/platform=iOS' \
  -configuration Release archive

或 Xcode：Product → Archive（⌘Y）→ Organizer → Distribute App。

13.4 Distribute 选项

场景选项说明
内测App Store Connect → TestFlight先 beta 测一遍
灰度Ad Hoc小范围（需设备 UDID）
正式上架App Store Connect自动签名 + 上传

13.5 App Store Connect 填写

  1. appstoreconnect.apple.com → My Apps → + New App。
  2. Bundle ID、版本号、build 号与 Archive 一致。
  3. App Information：Primary Category = Lifestyle；Subcategory = Productivity；Copyright = © 2026 清和日历。
  4. App Privacy：说明 Contacts / Calendars / Notifications / iCloud 数据用途。
  5. Review Information：准备测试账号（含 Contacts 演示）和 iCloud 演示步骤。
  6. 等待审核（通常 24-72 小时）。

14常见问题 FAQ

Xcode 打开 Package.swift 后没有 iOS App target？

SPM 不生成可执行 App target。按 §5 创建空 SwiftUI App target，加 Package Product 依赖即可。

真机 Run 报 "The app identifier cannot be registered"？

Bundle ID 冲突或没 Team。Signing & Capabilities → Team 选付费开发者账号，Bundle ID 改唯一值（com.<你的名字>.lunisolar）。

Widget Run 了但桌面没有？

真机长按桌面 → + → 搜 "Lunisolar" 添加。Widget Extension 不能单 Run，由宿主 App 带装。

CloudKit 同步不工作？

1) App ID 绑定 CloudKit；2) App Group 和 iCloud Container ID 一致；3) 真机 iCloud Drive 已开；4) 首次登录 Apple ID 后重启 App。

swift test 在 GitHub Actions 能过吗？

能。纯 SwiftPM 工程，CI 直接 swift test。CloudKit 走 Mock，Linux 环境也全绿。

后台切回后刚加的事件丢了？

已修复：App 在 scenePhase == .background/.inactive 时调用 EventStore.flushPendingSave() 立即落盘，避免 0.5s 防抖窗口内系统终止进程丢数据。
